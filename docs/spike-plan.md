# Spike 01 — Formula coverage and Excel equivalence on real spreadsheets

Status: v1 · 2026-11-17 · Time box: 2 days (Nov 18–19) · Decision owner: Collins
Purpose: replace guesses with measured numbers before committing three weeks.

> This spike is throwaway research code. It lives in `spike/` and is **not** the product. Nothing here is reused without going through the architecture stage.

## Questions the spike answers

| ID  | Question                                                                 | Pass threshold                                                                   |
| --- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| Q1  | Which Excel functions do real corporate spreadsheets use, and how often? | Top-40 functions cover ≥ 70% of formula cells                                    |
| Q2  | Can generated TypeScript reproduce Excel's cached values on real files?  | ≥ 90% exact match on cells using supported functions                             |
| Q3  | How often do HyperFormula and LibreOffice disagree with each other?      | Disagreement < 2% on supported cells, and every disagreement explainable         |
| Q4  | Do simple heuristics find the known real-world errors?                   | ≥ 30% of catalogued errors flagged (this is a value signal, not a gate)          |
| Q5  | Does the Kiro spec → property-test flow work for our kind of property?   | At least one property test generated by Kiro from an EARS requirement, run green |

**Go/no-go:** Q1, Q2 and Q3 must pass. Q4 and Q5 inform the plan.

## Data

- **Enron spreadsheet corpus** (Hermans & Murphy-Hill, 2015): ~15,000 real corporate `.xlsx`/`.xls` files, publicly available for research. Download from the authors' published source (`www.felienne.com/enron` redirects to the hosted archive; confirm the live link on day 1 and record it in `scripts/fetch-corpus.sh`).
- **Real-world error collection** (Schmitz & Jannach, 2016), derived from the Enron corpus. Locate the public dataset link from the paper and record it.
- Use only `.xlsx` files that contain at least one formula. `.xls` (binary) files are out of scope for the spike.

**Privacy rule:** raw corpus files are never committed to the repo. Scripts download them to `spike/data/` (git-ignored). No file contents, names or figures from the corpus appear in docs or demos without review.

## Tasks (in order)

### A. Function census (Q1) — ~3 hours

1. `scripts/fetch-corpus.sh`: download and unpack the corpus into `spike/data/enron/`.
2. `spike/census.ts`: for every `.xlsx`, read all formula strings with SheetJS (`cellFormula: true`); tokenise function names; count (a) formula cells per function, (b) files using each function.
3. Output `spike/out/census.json` and `spike/out/census.md` (table: function, cells, % of cells, files, cumulative %).
4. Record: total files, files with formulas, total formula cells, unique formulas.

### B. Cached-value equivalence (Q2) — ~6 hours

1. Pick the 300 files with the most formula cells among those whose functions are ≥ 95% inside the top-40 set from A.
2. `spike/equiv.ts`: for each file, load with SheetJS **keeping cached values** (`cellNF`, `cellText`, no recalculation), then load the same file into HyperFormula and recalculate.
3. For every formula cell compare: cached Excel value vs HyperFormula value. Numeric compare with tolerance 1e-9 relative; strings exact; errors by error type; dates as serial numbers.
4. Output `spike/out/equiv.json`: per file and overall — cells compared, matched, mismatched by function, top mismatch reasons.
5. **Then** take 10 of those files and hand-generate TypeScript for one output cell each (this is the real test of code generation, not of HyperFormula). Compare generated-code output vs cached value for the file's actual inputs. Record results in `spike/out/codegen-sample.md`.

### C. Independent-judge agreement (Q3) — ~3 hours

1. Install LibreOffice headless locally (`brew install --cask libreoffice`).
2. `scripts/lo-recalc.sh`: convert each of the 300 files via `soffice --headless --convert-to xlsx` into `spike/out/lo/`, which forces a recalculation and re-saves cached values.
3. Compare LibreOffice's cached values to Excel's original cached values and to HyperFormula's. Output `spike/out/judges.json` with three-way agreement rates and a list of disagreeing functions.
4. Time one GitHub Actions run on 50 files; record minutes.

### D. Error-detection hit rate (Q4) — ~3 hours

1. Implement five detectors over the formula graph: hard-coded constant inside a formula that elsewhere references a cell; range that stops short of the data block; formula in a column that differs from its neighbours; division whose denominator can be zero or blank; reference to an empty cell.
2. Run over the error collection; count flagged vs catalogued. Output `spike/out/detect.md`.

### E. Kiro flow check (Q5) — ~2 hours, done first on day 1

1. Open the repo in Kiro. Confirm steering files load (ask Kiro "what are your steering rules?").
2. Run the spike as a Kiro spec (`.kiro/specs/spike-01-formula-coverage/`). Let Kiro generate requirements → design → tasks, review each, then execute.
3. Ask Kiro to derive a property-based test from requirement R2 ("WHEN a supported formula is evaluated THE SYSTEM SHALL produce the cached Excel value"). Record whether it works and what the generated test looks like.
4. Note what Crew and Powers currently offer in the installed Kiro version (menu names, docs links). Record in `spike/out/kiro-notes.md`.

### F. Competitor check — ~2 hours, day 1, by Claude (not Kiro)

SpreadsheetWeb, Causal, Rows, Coefficient, Mito, Airtable formula export, "xlsx to code" tools, formulas.js, SheetJS Pro, Microsoft Power Fx. Record: what each does, whether it (a) produces owned code, (b) proves equivalence, (c) detects errors. Output `docs/competitors.md`.
